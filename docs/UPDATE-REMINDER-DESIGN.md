# 更新提醒设计

v0.2.1 的问题：自动检查默认关闭；开了也只在启动时查一次（菜单栏应用常常几周不重启）；查到新版本后只在**右键**菜单顶部多一项（左键打开的是面板），几乎没人看得到。
原型：`docs/prototypes/update-reminder.html`（2026-10-06 用户确认，「按推荐做」）。

## 1. 决策

| # | 决策 |
| --- | --- |
| U1 | 频率：每天一次。启动时到期就查；运行期间每小时判断一次是否到期；Mac 从睡眠中唤醒时也判断一次。只读取 GitHub 最新正式版的版本号，不上传任何数据 |
| U2 | 开关改名：「每周检查更新」→「自动检查更新」，说明「每天从 GitHub 读取一次最新版本号，不上传任何数据」。沿用原来的设置键，老用户的选择不变 |
| U3 | 新用户：欢迎页底部「登录时自动启动」下方加「有新版本时提醒我」，**默认勾选**、可取消；第一次显示欢迎页时把开关设为开，之后欢迎页只反映当前设置（从菜单重开欢迎页不会改动用户的选择） |
| U4 | 老用户（已完成过欢迎页、自动检查是关的、从没回答过）：升级后第一次打开面板，顶部蓝色横幅问一次「有新版本时提醒你吗？」——「提醒我」打开开关并立即检查一次；「不用了」保持关闭。无论选哪个都不再问 |
| U5 | 发现新版本：菜单栏图标右上角出现**蓝点**（强调色）；右键菜单顶部「新版本 x 可用…」；面板顶部蓝色横幅「新版本 x 可用」；「设置 › 关于」显示新版本与按钮。没有系统通知（需要通知权限，打扰） |
| U6 | 横幅每个版本提醒一次：「稍后」只隐藏这个版本的横幅（记住版本号，重启后仍有效），蓝点与菜单项保留；出现更新的版本时再提醒 |
| U7 | 记住最近查到的版本号与发布页地址：重启后不联网也能立即显示蓝点与横幅；当前版本已不低于它（用户升级了）时清除 |
| U8 | Homebrew 安装（存在 `/opt/homebrew/Caskroom/cubby` 或 `/usr/local/Caskroom/cubby`）：横幅主按钮为「复制升级命令」（`brew upgrade --cask cubby`，带本应用写入标记、不进历史），另有「更新内容」打开发布页；其余为「查看并下载」打开发布页 |
| U9 | 横幅样式：与权限横幅同一位置与结构，但用强调色（蓝）底而不是橙色；排在权限类提醒之后、「已暂停记录」之前 |
| U10 | 隐私说明（PRIVACY.md、README）改为：自动检查在新安装时于欢迎页默认勾选、可随时关闭；每天一次；只读取版本号 |

## 2. 实现

| 层 | 内容 |
| --- | --- |
| CubbyCore | `AppSettings`：检查间隔改为 1 天；新增「最近查到的版本 + 发布页地址」「稍后的版本」「是否回答过询问」三项持久化设置；纯函数 `UpdateReminder`（给定设置、当前版本、是否完成欢迎页 → 是否显示蓝点、横幅是「新版本」「询问」还是没有）与 Homebrew 检测（路径可注入），全部单元测试 |
| 应用 | `UpdateCoordinator`：每小时与唤醒时检查是否到期、记住结果、发布可观察的状态；菜单栏蓝点；面板横幅（`PanelWarning` 新增两种，蓝色样式，「稍后」持久化）；关于页；通用设置文案；欢迎页勾选项 |
| 测试 | 单元测试覆盖 U1–U8 的判断；`make e2e-panel` 场景：新版本横幅与「稍后」、Homebrew 变体复制命令、询问横幅的两个按钮、升级后清除 |
